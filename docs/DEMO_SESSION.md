# Demo — One Complete Multi-Turn Session

Generated by `tools/demo_session.py`. Not hand-edited. See [Reproducibility](#reproducibility) for how to regenerate it.

## What this demonstrates

One real session, start to finish, against the frozen Agent that produced our
reported TechnicalScore. It shows the three mechanisms the system runs on:

- **evidence accumulates** — each customer reply joins the lexical query and stays,
  split at clause boundaries so each stated constraint scores on its own (E013);
- **clarification opens wide, then narrows** — the first two turns ask the
  open-ended `other`, then the attribute is chosen from the candidates themselves;
- **the ranking moves** as evidence arrives, until the target reaches the Top 10.

The Agent never receives the target. Customer messages come from the published
simulator in `evaluator/local_evaluator.py`; the Agent is driven only through
`reset()` and `respond()`.

## What to notice

- The clarification attribute changes across turns: `other`, `other`, `style`.
  Turns 1-2 ask the open-ended `other` unconditionally: most of a shopper's
  constraints do not fall into any one attribute category, so an open question
  elicits more per turn than a well-chosen narrow one. From turn 3 the attribute
  is scored against that turn's own Top 10, so the Agent asks about what its
  current candidates disagree on. Both halves are E013; neither works alone.
- The recommendation list is not static: turn 1 opens with `B0196A59GY` at rank 1 and the final turn opens with `B09YMTWDXJ`.
- The target reaches rank 1 at turn 3, and the
  session stops there — the evaluator's stop-on-first-hit rule.
- **A visible limitation.** Evidence is append-only: after the customer says
  "ignore my earlier preference", the earlier wording still remains in the
  accumulated query. The system has no semantic supersession, so the override
  is absorbed as additional evidence rather than as a replacement. An
  erase-everything reset was tested and made results worse (E005, reverted);
  a finer-grained policy was never tested. See the README's Limitations.
- Every turn reports `usage` of 0 prompt / 0 completion tokens. No model is
  called at any point.
